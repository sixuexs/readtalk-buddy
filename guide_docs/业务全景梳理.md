## 1. 产品定位与总体架构

**定位**:基于多智能体的社交能力提升平台。通过 AI 情景模拟训练社交沟通能力,以多维评分与用户画像量化能力变化,通过周训练计划、针对性训练与周期总结形成完整的训练闭环;同时以关系运维能力辅助用户维护真实社交关系。

**运行形态**:单用户演示版(`userId=1`,画像文档 `id="default"`),无登录鉴权(个人中心"退出登录"为演示占位)。

**技术栈**:

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | uniapp + Vue 3 + TypeScript + ECharts | H5 与微信小程序双端(条件编译) |
| 后端 | Spring Boot 3.5(Java 17 目标,实际运行 JDK 25) | REST API,统一响应 `{code, data}`,`code=0` 为成功 |
| Agent 框架 | Spring AI Alibaba Graph(ReactAgent × 5) | 弱中心注册,Agent 间通过 Spring 事件与 MongoDB 协作 |
| LLM | DeepSeek(deepseek-v4-flash,推理型) | `application.properties` 配置;`max-tokens=8192` |
| 存储 | MongoDB(主存储)+ MySQL(JPA 投影,部分链路未启用) | 库划分原则见 C 文档 §0.1 |

**两条业务主线**:

```
[训练线] 能力训练闭环
  情景模拟(主题 × 角色性格 × 可选书友) → 多轮对话 → AI 评分(五维 + 16 子技能 + 证据)
    → 会后复盘(评分展示 / 状态自评 / 文字复盘)
      → 评分完成事件 → 能力统计刷新(纯规则) + 训练任务自动完成判定
        → 提升计划页:诊断(子技能与证据下钻)/ 周训练计划(任务与提交点评)/ 成长(周报、徽章、连续天数)
          → 周训练计划反向驱动训练:针对性模拟(注入练习重点,角色配合创设练习场景)

[关系线] 真实社交关系维护
  个人名片(兴趣/标签/性格) → 破冰分析(情境 + 对方名片 → 开场白/话题/注意事项)
    → 联系人建档或复用 → 模拟训练可绑定书友,评分计入亲密度深度/质量分量
      → 亲密度四分量计算(E/C2) → 预警规则(E/C3) → 关系图谱展示
        → 个性化建议(E/C4) → 提醒冷却管理、联系人删除
```

## 2. 功能模块清单

### M1 首页仪表盘(`pages/home/home.vue`)

- **功能**:能力雷达(五维均分)、总分趋势折线(近 10 次评分)、快捷功能入口(2×3)。
- **数据**:`GET /api/user/profile`(雷达、趋势);`GET /api/plan/current`(提升计划入口的任务进度角标,请求失败时静默隐藏)。
- **说明**:图表使用 ECharts,H5 用 DOM 容器、小程序用 canvas 2d(经 `utils/wx-canvas` 适配)。

### M2 情景模拟训练(`pages/simulation/simulation.vue`)

- **功能**:配置页(5 主题 × 4 角色性格 × 可选练习对象书友,支持随机配置)→ 聊天页 → 结束进入复盘。
- **两种进入方式**:
  1. 自由训练:用户自选配置,`POST /api/simulation/start`;
  2. 针对性训练:从提升计划页跳转,携带 `focusSubSkill`(练习重点子技能)与 `prescriptionTaskId`(关联任务),经模块级 store(`store/simFocus.ts`)传参(小程序 tabBar 页不支持 URL 参数)。此模式下后端计算该子技能近 3 场均分作为基线(`focusBaseline`),并在角色 system prompt 中注入练习配合指令(见《能力提升模块重构设计》§5),聊天页标题栏显示当前练习重点。
- **数据**:`conversations` 集合;书友列表复用 `GET /api/relation/graph`。
- **虚拟人物**(`pages/simulation/virtual-characters.vue`):自定义 AI 角色库(增删查),供破冰分析与模拟训练选用,存 `virtual_characters` 集合。

### M3 AI 评分与会后复盘(`pages/assist/review.vue`、`pages/social/chat-history.vue`)

- **功能**:
  - 评分:对整场对话单次 LLM 调用,输出五维分(0-100)、总分、评语、优点/建议标签,以及 **16 项子技能分**(`subScores`,无观察机会的项为 null)与 **原话证据**(`evidence`,0~4 条,含用户原话片段、问题说明、改进示范)。评分 prompt 含横切仲裁规则与防刷分约束,与 B 文档对齐。
  - 复盘页:总分与五维条形、AI 评语与标签、针对性训练场次显示"练习重点前后对比"(基线 → 本场,含差值)、本场证据列表、状态自评(多选标签)与文字复盘保存。
- **接口**:`POST /api/simulation/score`(失败时返回 `code=502` 与提示信息,不返回 500)、`GET /api/simulation/history`、`POST /api/simulation/self-review`。
- **事件**:评分成功后发布 `ScoringCompleted`,触发统计刷新、任务完成判定与亲密度联动(见 §6)。
- **容错**:子技能与证据解析采用白名单校验 + 宽容降级(缺失记 null / 空数组,未知键记日志),任何解析失败不影响五维主分入库。

### M4 用户画像与能力统计(`UserProfileTools` / `user_profile` 集合)

- **功能**:跨会话聚合能力数据,供首页、提升计划页、名片页、破冰分析(我方信息)、关系建议(画像上下文)读取。
- **两条更新路径(职责分离)**:
  1. `refreshStats(boolean fromScoring)`——纯规则、零 LLM:五维均分、总分、评分历史、会话数、**子技能均分与样本数**、**徽章判定**、**连续训练天数**(仅评分事件触发更新)。由评分完成事件自动调用;不修改评估文本与任何任务、打卡数据。
  2. `assessAbility()`——LLM 生成评估文本(总评、优势、短板、提升路线),仅由用户在前端手动触发(`POST /api/simulation/profile/assess`);周目标字段仅在首次生成时写入,此后不再覆盖(避免重置用户进度)。
- **字段**:`avg*` 五维均分、`overallScore`、`scoreHistory[]`、`assessment/topStrengths/topWeaknesses/improvementPlan`(评估文本)、`weeklyGoals/weeklyGoalsStatus/weeklyGoalSubmissions`(旧版周目标及打卡附言,已被周训练计划取代,字段保留)、`subSkillAverages/subSkillSampleCount`(子技能聚合)、`badges[]`(徽章达成记录)、`streakDays/bestStreak/lastActiveDate`(连续训练)、名片字段(见 M8)。

### M5 能力提升训练闭环(`pages/plan/plan.vue` + `PlanService` 等,2026-09 重构新增)

模块的完整功能设计见《能力提升模块重构设计》,此处概述:

- **页面结构**:提升计划页分三段——今日(周进度、推荐训练、任务列表)、诊断(评估文本、雷达下钻至子技能与原话证据)、成长(趋势切换、维度等级、连续天数、徽章、周报时间轴)。
- **诊断**:五维之下细分 16 项子技能(词典常量 `SubSkillConstants`,前后端短名一致);每项均分可下钻到历史证据(用户原话 + 问题说明 + 改进示范,`GET /api/user/evidence?subSkill=`);样本不足(含分场次 < 2)的子技能不参与诊断并置灰提示。
- **周训练计划**(`training_plans` 集合,按 ISO 周版本化):规则层统计选出优先改进子技能,LLM 生成 3~5 个结构化任务(应用内训练 / 真实场景任务 / 认知任务),全部经过白名单与结构约束校验,不足时按模板补齐;LLM 失败时整体走规则模板,不阻塞页面。
- **任务完成方式**:
  - 应用内训练任务:评分完成事件自动判定(子技能分达标或完成针对性训练场次即累计进度,按会话去重),无需手动确认;
  - 真实场景 / 认知任务:用户提交文字记录(≥10 字),LLM 依据任务标准判定是否合格并给出点评;单任务最多提交 3 次。
- **推荐训练**:`GET /api/plan/recommendation` 依据优先改进子技能查静态映射表(子技能 → 主题 × 角色性格 × 练习场景创设指令),前端一键进入针对性训练。
- **周期与总结**:周切换采用按需触发(读取接口时检查,无定时任务);切换时将上周未完成任务置为过期、归档计划、生成周报(`weekly_reports`:完成度、子技能变化、正向证据摘录由规则计算,总结与下周任务草稿由 LLM 生成,失败时用模板文案);用户可采纳下周草稿(冻结快照,周切换时直接实例化)或重新生成草稿。
- **成长数据**:子技能徽章(近 3 场均分 ≥80 为掌握、≥90 为进阶,只升不降)、连续训练天数、维度等级(前端按阈值现算,不落库)。

### M6 破冰分析(`pages/icebreak/icebreak.vue`、`icebreak-result.vue`)

- **功能**:输入当前情境(预设或自定义)、对方名片信息(三选一:已有书友 / 虚拟人物 / 文本粘贴)、我方心情状态与补充说明,LLM 生成开场白(3 条)、建议话题(3 条)、注意事项;结果页支持分区重新生成。
- **副作用**:自动创建或复用联系人(按 id 优先、按姓名去重),新联系人发布 `ContactAdded` 事件;联系人信息以本次分析为准刷新。
- **接口**:`POST /api/simulation/icebreak`、`POST /api/simulation/icebreak/refresh`。

### M7 关系图谱与关系运维(`pages/relation/graph.vue` + E 模块)

- **功能**:三环关系图谱(按亲密度分区)、预警角标、联系人详情(个性化建议、提醒冷却/恢复、删除)、关系洞察面板。
- **E 模块分层**(详见 E 文档):常量层(C1)/ 亲密度计算(C2,四分量:时效 0.35、频率 0.25、深度 0.20、质量 0.20,双写收口)/ 预警规则(C3,沉寂、滑落、质量三类)/ LLM 建议生成(C4,light/full 两档,规则兜底)/ API 层(C5,`RelationTools`)。
- **接口**:`GET /api/relation/graph`、`GET /api/relation/contacts/{id}/advice?mode=`、`POST .../dismiss`、`POST .../resume`、`DELETE /api/relation/contacts/{id}`。
- **数据**:MongoDB `contacts`(唯一事实源);MySQL `contact` 表为单向投影(`ContactSavedEvent` → `ContactSyncListener`,MySQL 不可用时仅记日志)。

### M8 个人名片与个人中心(`pages/namecard/namecard.vue`、`pages/profile/profile.vue`)

- **名片**:编辑显示名、头像(emoji)、简介、状态签名、性格、兴趣、标签;`GET/PUT /api/user/profile`(白名单字段更新,文档不存在时自动创建)。名片数据被破冰分析(我方信息)与关系建议(用户画像上下文)引用。
- **个人中心**:菜单入口(名片 / 提升计划 / 破冰分析 / 社交记录);"退出登录"为演示占位,无实际鉴权。

### M9 社交记录(`pages/social/social.vue`、`chat-history.vue`)

- **功能**:会话列表(评分、主题、消息数,左滑删除)、单会话消息回放、补评分入口。删除关联书友的会话后自动重算该书友亲密度。
- **接口**:`GET/DELETE /api/simulation/sessions`、`GET /api/simulation/history`。

### M10 沟通辅助(复盘版,已实现)

- **定位**:线下真实沟通复盘 —— 录音→转写→说话人归属确认→五维评分→复盘报告;区别于纯线上产品,落地「聚焦线下」创新点。
- **链路**:`pages/assist/record.vue`(录音,mp3/16k/单声道/≤5min,知情同意 + 仅录本人)→ `POST /api/simulation/assist/transcribe`(`AliyunAsrClient`,阿里云百炼 `qwen-audio-3.1-asr-flash` 同步版,Base64 免 OSS,`speaker_diarization_enabled`)→ `pages/assist/confirm.vue`(归属确认:我/书友/陌生人,可逐句删除)→ `POST /api/simulation/assist/review`(`CommAssistService`)→ 复用 `review.vue` 展示。
- **评分**:复用 `SimulationService.scoreDialogueText`(与情景模拟同一套五维 + 16 子技能 + 证据链,口径一致);旧 `CommAssistTools` 简化评分已弃用。
- **落库**:MongoDB `conversation`(虚拟会话,`origin=offline`,承载评分/画像/事件链)+ `conversation_detail`(多人逐句,`speakerRef`=Mongo contact id);MySQL `interaction_meta` + `evaluation_record`(`source=1` real)。三库以同一 `reviewId` 串联。
- **隐私**:音频仅内存态持有、转写后即释放,不落盘不入库;声纹不接收不存储;转写文本入 LLM 与落库前做轻量 PII 脱敏(`TextMaskUtil`,`assist.mask-pii=true`)。
- **降级**:未配置 ASR 密钥进入 Mock 模式返回示例转写;MySQL 写入失败只记日志不阻断复盘;沙龙 `annotation` 暂 null,亲密度走时效+频率降级模式。
- **待办**:沙龙逐句聚合(需 annotation 回填)、录音分段续接(>5 分钟需切异步 filetrans)、删除复盘时级联清理 `conversation_detail` 与 MySQL 记录。

### M11 演示与种子数据

- `DemoAdminController`(`/api/demo/reset`,仅 `demo` profile):一键重建演示数据。
- `VirtualCharacterSeed`(启动时补齐虚拟人物)、`IntimacyValidationSeed`(`seed` profile)、`DemoShowcaseSeed`(`demo` profile)。

## 4. 接口清单

### /api/simulation(SimulationController)

| 方法 | 路径 | 前端调用 | 说明 |
|---|---|---|---|
| GET | `/config` | 是 | 主题与性格选项(当前硬编码于 `getConfig()`) |
| GET | `/scenario` | 封装未用 | 场景信息(占位实现) |
| POST | `/start` | 是 | 建会话并返回开场白;请求含 `theme/personality/relatedContactId`,针对性训练时另含 `focusSubSkill/prescriptionTaskId`,响应含 `focusBaseline` |
| POST | `/send` | 是 | 发送消息并返回 AI 回复 |
| GET | `/history` | 是 | 消息 + 评分(含 `subScores/evidence`)+ 自评 + 练习重点对比 |
| GET | `/sessions` | 是 | 会话摘要列表 |
| DELETE | `/sessions/{id}` | 是 | 删除会话(关联书友则重算亲密度) |
| POST | `/score` | 是 | AI 评分;成功返回评分与 `focus` 对比(针对性场次);LLM/解析失败返回 `code=502` 与提示 |
| POST | `/self-review` | 是 | 保存自评(selfState/selfComment) |
| POST | `/agent`、GET `/agents` | 否 | 多智能体演示入口 |
| GET | `/profile` | 否 | 画像 Agent 视图(前端用 `/api/user/profile`) |
| POST | `/profile/assess` | 是 | 手动重新生成评估文本;不覆盖周目标与打卡状态 |
| GET/POST | `/contacts*` 系列 | 否 | 旧关系运维接口,已由 `/api/relation/*` 取代,保留未下线 |
| POST | `/icebreak`、`/icebreak/refresh` | 是 | 破冰分析与分区再生成 |
| GET/POST/DELETE | `/virtual-characters[/{id}]` | 是 | 虚拟人物管理 |
| POST | `/assist/analyze`、`/assist/score` | 否 | 沟通辅助(前端未接入) |

### /api/user(UserProfileController)

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/profile` | 完整画像文档(名片字段 + 能力统计 + 子技能聚合 + 徽章 + 连续天数) |

## 6. 事件与后台流程

```
SimulationService.scoreConversation() 成功
  └─ 发布 ScoringCompleted(sessionId, score)
       ├─ UserProfileListener → refreshStats(true)
       │    · 五维/总分/评分历史/子技能聚合/徽章/连续天数(纯规则,零 LLM)
       │    · 不修改评估文本、周目标、任务进度
       ├─ PlanService.onSessionScored(sessionId)
       │    · 当前周计划中自动判定型任务的进度累计(按会话去重,失败仅记日志)
       └─ IntimacyService(骨架监听)
            · 会话绑定书友时,评分计入亲密度深度/质量分量并重算

IceBreakTools.analyzeCard()(仅新联系人)
  └─ 发布 ContactAdded(预留联动)

联系人保存路径
  └─ 发布 ContactSavedEvent → ContactSyncListener → ContactService 写 MySQL contact(投影)
```

**按需周切换**(无定时任务):`GET /api/plan/current`、`/recommendation` 等读取入口先检查当前 ISO 周;若活动计划属于以往周,则依次执行:未完成任务置过期 → 生成上周周报(已存在则跳过)→ 计划归档 → 生成新周计划(存在已采纳草稿时直接实例化)。计划生成持有互斥锁,并发请求返回 `generating` 状态由前端轮询。

## 7. 评价体系现状

- **两层结构**:五维整篇评分(B 文档口径,唯一权威分,综合分 = 五维等权平均)+ 16 项子技能(诊断粒度,短名 snake_case 全系统统一,词典见 `SubSkillConstants` 与《能力提升模块重构设计》§3)。子技能判据服从 B 文档横切仲裁规则;无观察机会时输出 null,不强制打分。
- **评分调用**:单次 LLM 调用输出全部字段;推理型模型可能耗尽输出预算返回空内容,已配置空内容紧凑重试一次;`max-tokens` 由 4096 调整为 8192。
- **解析容错**:五维缺省 50 并记日志;子技能白名单校验(未知键告警);证据坏条目丢弃;子技能层失败不影响主分入库;评分接口整体失败返回 502 语义。
- **旧版周目标**:`weeklyGoals` 打卡(附复盘文字)接口仍可用,但提升计划页已由周训练计划取代,字段与接口保留兼容。
