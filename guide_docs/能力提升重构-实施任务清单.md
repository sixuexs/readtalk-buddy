## 1. 环境与常用命令

| 事项 | 命令 / 位置 |
|---|---|

| 依赖服务 | MongoDB(localhost:27017,库 `readtalk_buddy`,必需)、MySQL(localhost:3306,`readtalk_buddy`,JPA 启动依赖)、DeepSeek API(`application.properties`) |

**实施硬约束**(后续迭代继续适用):

1. 自由训练(不传练习重点参数)与五维主评分流程保持既有行为;
2. 子技能、证据、计划生成、点评等 LLM 环节失败时必须降级(null/空/模板/错误码),不得阻断主流程或返回未处理异常;
3. 不修改 MySQL 侧结构(本期新增数据均为 MongoDB 文档);
4. 子技能短名、集合名、既有接口语义冻结,变更须先修订设计文档。

## 4. 回归验证清单

发布前或改动相关链路后执行。前置:MongoDB/MySQL 服务运行、后端启动、`npm run dev:h5`。

**R0 基线**

1. `mvnw test` 全量通过;`npm run type-check` 通过。
2. `GET /api/simulation/config` 正常返回。

**R1 统计与旧数据兼容**

1. 提升计划页(或 `PUT /api/user/profile/weekly-goals`)勾选任一旧周目标:无附言被拒(400),附 ≥5 字附言成功。
2. 对任一历史会话执行 `POST /api/simulation/score`。
3. `GET /api/user/profile`:勾选状态与附言保持不变;`avg*`、`subSkillAverages`、`streakDays` 已更新;后端日志显示统计刷新且无评估生成调用。

**R2 训练闭环(核心场景)**

1. 完成一场新模拟并评分 → 复盘页出现子技能证据(quote 可与对话原文对应)。
2. 提升计划页诊断段:雷达/维度按钮 → 子技能条 → 证据卡 → 跳转对应会话记录;样本不足子技能置灰。
3. `GET /api/plan/current`:含 ≥3 场子技能评分数据时生成计划;任务卡渲染(auto 任务无勾选控件)。
4. 推荐卡进入针对性训练:直达聊天页并显示练习重点;角色按映射指令创设练习场景;结束评分后复盘页显示"基线 → 本场(差值)"。
5. 回到提升计划页:对应 auto 任务进度 +1;对同一会话重复评分不重复计进度。
6. evidence 任务提交:<10 字被拒;合格记录通过并 progress+1;连续 3 次后锁定。
7. 任务卡"为什么是这个任务"展开显示关联证据。
8. `POST /api/plan/regenerate`:旧计划归档(mongosh 可见两份文档),新计划 active。

**R3 周期与总结**

1. 将 active 计划 weekKey 改为上一周:`mongosh readtalk_buddy --eval "db.training_plans.updateOne({status:'active'},{\$set:{weekKey:'<上周键>',weekStart:ISODate('<上周一>'),weekEnd:ISODate('<上周日>')}})"`。
2. `GET /api/plan/current` 触发切换:上周任务 expired、计划 archived、`weekly_reports` 生成、新周计划 active。
3. 周报完成度数字与 mongosh 手算一致。
4. `POST /api/plan/reports/<上周键>/adopt` → 再次执行步骤 1-2 → 新计划 `generatedBy=adopted` 且任务与草稿一致。
5. 徽章:构造某子技能近 3 场 ≥80 后触发一次评分 → `user_profile.badges` 写入,前端成长段显示,新徽章提示出现一次。

**R4 无回归抽查**

1. 自由训练(不带练习重点):start/send/score/history 行为与重构前一致,systemPrompt 无注入段。
2. 关系图谱、破冰分析、个人名片、社交记录各抽查一条主流程。
3. `npm run build:mp-weixin` 通过;小程序端提升计划页三段可用(维度按钮、提交弹层、周报横滑)。
4. 旧会话(无 subScores)在诊断、趋势、聚合中静默跳过,页面无报错。
